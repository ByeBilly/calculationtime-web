Try it now - no key needed

Reference-data endpoints are public. This runs a real request from your browser (the API sends open CORS headers). They support q to filter and limit to cap the rows.

curl 'https://api.calculationtime.com/v1/data/http-status?q=teapot'

curl 'https://api.calculationtime.com/v1/data/stars/bright?q=crux'

Every data response carries dataset_version, source and count, so you always know what you are reading and how fresh it is.

Astronomy engines: the Crux Sky Clock

Three endpoints turn a sidereal clock model, calibrated to Parkes Observatory, into positions you can use in your own instruments and dashboards. It is the same engine behind the Crux Sky Clock calculator on the main site.

EndpointWhat it returnsCredits
POST /v1/astronomy/crux-midnightSidereal position of the Crux clock hand at local midnight for a run of consecutive dates2 per call
POST /v1/astronomy/crux-hourlyA full 24-hour sidereal breakdown for one local date5 per call
POST /v1/astronomy/crux-currentLive clock-hand position and the Parkes alignment delta for a timestamp2 per call
 
curl 'https://api.calculationtime.com/v1/astronomy/crux-midnight' \
  -X POST \
  -H 'X-API-Key: YOUR_KEY' \
  -H 'Content-Type: application/json' \
  -d '{"start_date":"2026-03-31","days":3,"timezone":"+10:00"}'

Access, limits and honesty

Public

Status, health, OpenAPI, the UTC clock and all reference data. No key. Observed limit: 60 requests per minute, reported in x-ratelimit-* headers.

Beta keys

Calculation endpoints require a key, issued privately on request. Send it as X-API-Key. The contract also declares Authorization: Bearer.

Credits

Protected calls are credit-metered. GET /v1/account/credits and /v1/account/limits show your balance and plan limits and are free to call.

No SLA yet

The status endpoint says so deliberately. Reliability claims stay conservative until monitoring history exists.

Beta access is by request, not self-service. Pricing, a customer dashboard and automated key rotation are not live yet.

On the roadmap planned, not live

  • Published request and response schemas for every calculation endpoint (today most POST bodies are described only as free-form objects).
  • Self-service key requests, a usage dashboard and public pricing.
  • Larger reference tables: full Unicode block list, a longer bright-star catalogue and material properties beyond density.
